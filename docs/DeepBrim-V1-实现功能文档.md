# DeepBrim V1 实现功能文档

> 版本：v1.1.0（manifest 已同步）
> 平台：Microsoft Edge · Manifest V3
> 定位：DeepSeek 网页版（chat.deepseek.com）上下文仪表盘
> 文档日期：2026-10-31

---

## 一、项目概述

DeepBrim 是一个轻量 Edge 扩展，在 DeepSeek 网页版右下角挂一个可拖拽的圆盘，实时显示当前会话的上下文占用（官方真值优先），并支持按会话缓存、历史回补和本地校准。

设计约束：

- 不读取、不保存对话正文，只保留数字
- 所有计算在本地完成，不上传任何数据
- 不改动 DeepSeek 页面原有请求，只旁路读取

## 四、数据口径

### 4.1 显示优先级

```
官方真值 officialTotal  →  历史基线 baselineValue  →  无数据（—）
```

文本估算只作为兜底，且必须标记来源，绝不覆盖官方真值。

### 4.2 数据来源与可信度

| 来源 | 字段 | 可信度 |
|------|------|--------|
| 流式响应 | `accumulated_token_usage` | 官方真值 |
| 历史消息 | 最后一条消息的 `accumulated_token_usage` | 官方真值 |
| 历史文本估算 | 中文 ×0.6 + 其余 ÷3.5 | 估算，仅兜底 |
| 附件 | `update_file.token_usage` | 官方真值 |

### 4.3 本轮计算

```
有上一轮真值：本轮 = 本次 accumulated − 上一轮 accumulated
无上一轮真值：本轮 = 本次 accumulated − 历史基线（来源标记为历史）
两者都无：显示 —
```

### 4.4 上下文上限

- 默认 `1,000,000`
- 预设 `128,000` / `64,000`
- 自定义范围 `1,000 – 10,000,000`
- 仅影响百分比与圆环，不影响官方 Token 数字

## 五、缓存设计

### 5.1 存储位置

`chrome.storage.local`，每个会话一条记录：

```
deepbrim.cache.<chat_session_id> = {
  title,              // 会话标题（优先取历史响应中的 chat_session.title）
  officialTotal,      // 最近一次官方累计值
  officialPrevTotal,  // 上一轮官方累计值
  baselineValue,      // 历史基线（可能为真值或估算）
  baselineSource,     // 'message-field' | 'estimate' | 'unknown'
  attachmentTokens,   // 附件累计
  messageCount,       // 历史消息条数
  updatedAt           // 最近更新时间
}
```

另有两条独立配置：

```
deepbrim.limit  // 上下文上限
deepbrim.pos    // 圆盘位置（视口百分比 x/y）
```

### 5.2 写入时机

- 数据变化后 debounce 2 秒写盘
- 切换会话前 flush 上一个会话
- 页面 `pagehide` 时 flush
- 只有存在有效数据才写，避免空记录

### 5.3 会话切换

- 监听 URL 变化（500ms 轮询 `/chat/s/<uuid>`）
- 切走时先 flush，再读取目标会话缓存
- 缓存命中立即显示（标记 `缓存 · …`），不等待网络
- 进入非会话页（如首页）时清空显示

### 5.4 标题

标题优先取历史响应里的 `chat_session.title`；其次监听 `document.title` 变化（重命名后 2–3 秒内同步）；都拿不到时回退为 `会话 xxxxxxxx`。

## 六、技术实现要点

### 6.1 双世界脚本

| 脚本 | world | 职责 |
|------|-------|------|
| `inject.js` | MAIN | 能访问页面真实 `fetch` / `XHR`，负责拦截与解析 |
| `content.js` | isolated | 能访问 `chrome.storage`，负责 UI、缓存、设置 |

两个世界通过 `window.postMessage`（`source: 'deepbrim'` / `'deepbrim-ui'`）通信。

### 6.2 SSE 解析

- 使用 `response.clone()` 旁路读取，不破坏页面原有流
- 按空行分帧，解析 `event:` 与 `data:`
- `update_file` 事件按附件处理
- 递归查找字段，不写死路径
- `rawTail` 只保留最后 64KB 用于兜底正则

### 6.3 XHR 拦截

- 记录 URL 与请求头，重点保存 `Authorization`
- SSE 通过 `readyState 3` 的 `progress` 事件读取
- 用 `consumed` 游标只处理新增片段，避免整段拼接

### 6.4 历史回补策略

```
点「重新拉取历史」
  ├─ 有捕获的 history 请求 → 先发增量（沿用 cache_version）
  │    ├─ 返回新消息 → 取最后一条累计值，立即结束
  │    └─ 返回空 + MERGE + 本地有缓存 → 判定"已是最新"
  └─ 无缓存 / 增量失败 → 全量请求（去掉 cache_version、cache_reset_at）
        ├─ 成功 → 建立基线
        ├─ 失败 → 回退到请求头复放
        └─ 仍失败 → 保留缓存，提示失败
```

### 6.5 请求鉴权

1. 优先使用 XHR hook 捕获的真实 `Authorization`
2. 其次扫描 `localStorage` 中名称含 token/auth/credential/jwt 的值
3. 剔除浏览器禁止脚本设置的请求头后复放

### 6.6 内存控制

- `sessions` Map 只存数字与附件条目，不存消息原文
- 历史 JSON 解析后仅提取字段，出函数即被回收
- `rawTail` 上限 64KB
- 标记载荷使用独立流副本，不累积完整响应

## 八、已知限制

1. **全量历史较慢**：长对话需下载全部消息，实测约 12 秒；已通过"增量优先"把日常操作压到 100ms 级
2. **接口不支持分页参数**：无法只取尾部 N 条
3. **无正文 / 思考拆分**：SSE 未直接提供该分类，暂未实现
4. **无逐条角标**：规划在 V2，需处理虚拟滚动与 DOM 对应
5. **缓存仅本机**：`storage.local` 不跨设备；跨设备一致性依赖主动回补
6. **文本估算有偏差**：仅作为历史兜底，误差约 ±20%
7. **缺少图标**：尚未提供 16 / 48 / 128 图标资源

## 十、v1.1 健壮性修复（2026-10-31）

对静态审查列出的 14 条问题做了修复，共处理 13 条，明确跳过 1 条（#12，收益低于风险）。

### 10.1 高危（3 条）

| 编号 | 问题 | 修复方式 | 结果 |
|------|------|----------|------|
| #1 | `parseSessionId` 失败返回 `'unknown'`，可能把 A 会话数据写到 B 会话 | 返回 `null`；fetch / XHR 两条路径加守卫，缺 ID 直接跳过本轮；`applyHistory` 拒绝无效 ID | 不再产生 `unknown` 僵尸会话，不跨会话串数据 |
| #2 | `document_start` 时 `document.documentElement` 可能不存在，`appendChild` 抛错后 UI 静默消失 | 新增 `mountWhenReady()`：根节点存在则立即挂载，否则 `MutationObserver` 等待；布局动作延后到挂载完成 | UI 不再整块消失；元素在布局树中后再定位，不会贴在左上角 |
| #3 | SSE 流中断（停止生成 / 网络抖动）时 `flush()` 不执行，本轮不收尾、下轮虚高 | `parseStream` 改为 `try / catch / finally`，`finally` 必定 `flush()` | 中断时仍会上报本轮已抓到的用量，并正确更新 `previousLatest` |

### 10.2 中危（3 条）

| 编号 | 问题 | 修复方式 | 结果 |
|------|------|----------|------|
| #5 | 历史 baseline 取"最后一个有字段的消息"，倒序或字段稀疏时低估 | 取所有消息 `accumulated_token_usage` 的**最大值**；仅当全部缺失时才做文本估算 | 历史基线不再被低估 |
| #8 | `localStorage` token 匹配过宽，可能拿 csrf / theme 等假 token | key 黑名单 + 值结构校验（Bearer / JWT / 32 位以上不透明串）+ 候选打分 | token 兜底命中率与准确性提升 |
| #9 | 增量探测复用其他会话的 `cache_version`，误报"已是最新" | 仅当 `lastHistoryRequest` 的会话 ID 与目标一致时才走增量，否则直接全量 | 跨会话重拉不再出现"假最新" |

### 10.3 低危（7 条）

| 编号 | 问题 | 修复方式 |
|------|------|----------|
| #6 | 极小百分比显示 `0.0%`，像没工作 | `percent < 0.05` 显示 `<0.1%` |
| #7 | toast 在圆盘顶部时可能盖住面板 | 先避圆盘；若与面板重叠，改放到面板下方 |
| #10 | 切会话后仍停在设置页 | `switchSession` 时若不在数据页则自动回到数据页 |
| #11 | 多行 `data:` 用空串拼接，不符合 SSE 规范 | 改为 `join('\n')`，兼容未来多行响应 |
| #13 | 请求进行中再点圆盘，`spin()` 会中断持续转圈 | 重命名 `spinOnce()` / `db-spin-once`；请求中直接返回；提示"正在拉取历史，请稍候…" |
| #14 | 负差值被格式化成负数 Token | `formatTokens` 对负值返回 `<0` |
| #15 | 自定义输入等于预设值时，下拉仍停在"自定义" | `saveLimit` 保存后调用 `syncLimitSelect()` |
